\section*{Task 3 --- Inference service}
\texttt{service/app.py} validates every output against \texttt{schema.json} (exactly four keys, eight intents) and returns HTTP 500 with \texttt{invalid\_model\_output} otherwise;
\texttt{FAULT\_INJECT=1} replaces the output by the text \texttt{not json}. \texttt{/readyz} returns 503 until a background thread has downloaded the model from S3 (boto3, credentials from the environment, i.e.\ a Secret in Kubernetes).
Tests with an injected stub generator cover success and headers, invalid intent, extra key, fault injection and health/readiness (5 of the 9 tests; all pass).
\textbf{Not verified:} real model loading, the prompt/training format match, image size ($\le$2\,GB), the 50-request CPU/memory test.

\section*{Task 4 --- Kubernetes}
The manifest was written to the specification (namespace \texttt{app}, two initial replicas, rolling update, probes, HPA min 1 max 2 target 70\%). A unit test checks these fields in the YAML. It was never applied to a cluster, so scaling, rollout, rollback, recovery and cold-start behaviour are \textbf{unverified}.
