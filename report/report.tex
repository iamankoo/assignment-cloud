\section{Introduction and architecture}
A fixed JSON ``frame'' with exactly four keys (\tc{intent}, \tc{date}, \tc{time}, \tc{place}) is extracted from a short English command, e.g.\ \emph{``what is the weather in london''} gives
\tc{{"intent":"weather_query", "date":null, "time":null, "place":"london"}}. A 3.8B-parameter teacher (Phi-3.5-mini via Ollama) is far too large to serve on a laptop, so it is used
\emph{once, offline} to label 3{,}000 commands. A 70M-parameter student (EleutherAI Pythia-70M, Apache-2.0) is then fine-tuned to reproduce those labels --- \emph{sequence-level knowledge
distillation} (Kim and Rush, 2016) --- and only the student is deployed behind a FastAPI service on a two-node k3d cluster, with model weights kept in S3-compatible object storage
(SeaweedFS), never in the image or in Git.

\section{Task 1 --- Object storage and parallel teacher labelling}
\textbf{Design.} k3d (\tc{cluster/k3d.yaml}: 1 server + 1 agent, host port 8080 to 80) hosts SeaweedFS in namespace \tc{data} (single replica, S3 gateway :8333, 2\,GiB PVC, 1.5\,GiB memory limit),
with buckets \tc{datasets} and \tc{models} (\tc{scripts/upload.py}). The teacher prompt (\tc{prompts/teacher_prompt.txt}) states the four-key schema, the eight intents and the three slot rules
(copy verbatim, shortest phrase, otherwise null). Ollama is called with \tc{temperature=0}, \tc{seed=42}; the reply is stored \emph{exactly as generated} in the field \tc{teacher_raw}.

\textbf{Sharding.} An Indexed Job (\tc{completions}=\tc{parallelism}=2, namespace \tc{pipeline}) starts two pods whose \tc{JOB_COMPLETION_INDEX} serves as \tc{SHARD_INDEX}. Worker $i$ takes the records whose
0-based line number $n$ satisfies $n \bmod K = i$ ($K$=\tc{SHARD_COUNT}=2) and writes \tc{datasets/teacher/shard-}$i$\tc{.jsonl}. Each $n$ has exactly one residue, so shards are \emph{complete and disjoint} (no gap, no repeat);
for 3{,}000 records they are \emph{balanced} (1{,}500 each) \evC; all three properties are asserted by a unit test on 3{,}000 synthetic ids \evA. Workers are resumable (finished ids are skipped), so a restarted pod does not duplicate work.
Caveat: both workers share one host CPU for Ollama, so wall-clock speed-up may be well below 2$\times$ (\tc{OLLAMA_NUM_PARALLEL=2} allows two concurrent requests).

\textbf{Cleaning} (\tc{worker/clean.py}). Records are read from all shards, sorted by id, and rejected at the \emph{first} failing rule: (a) not valid JSON; (b) keys not exactly the four; (c) intent not one of the eight;
(d) a non-null slot that is not a string occurring in the command (case-insensitive); then (e) duplicate \emph{command text} (the smallest id is kept). The rest is written to \tc{datasets/v1/train.jsonl} with \tc{train.sha256}.
Because each record is counted once, $N_{\text{in}} = N_{a}+N_{b}+N_{c}+N_{d}+N_{\text{dup}}+N_{\text{kept}}$ always holds (asserted in tests \evA). The unit test uses six hand-written toy records \evI:

\section{Task 2 --- Student training by sequence-level distillation}
\textbf{Method.} Each example is the line \tc{Command: <text>} followed by the line \tc{JSON: <teacher JSON>}; the \emph{same prompt string} is used by \tc{train.py}, \tc{predict.py} and the service (checked by a test \evA). The loss is token-level cross-entropy on the
teacher's best sequence $y^{*}$ (prompt tokens masked with $-100$):
\[\mathcal{L}(\theta)=-\sum_{t=1}^{T}\log p_\theta\!\left(y^{*}_t \mid x,\,y^{*}_{<t}\right).\]
\textbf{Configuration} (\tc{training/config.yaml}, read by \tc{make train}; values are \evP): seed 42 (\tc{random} and \tc{torch}), learning rate $5\!\times\!10^{-5}$ (AdamW, weight decay 0.01, gradient clipping 1.0), batch size 8, 3 epochs, max length 128, first 1{,}500 cleaned records
(188 steps per epoch, 564 in total \evC), CPU, library versions pinned (torch 2.4.1, transformers 4.44.2, tokenizers 0.19.1, numpy 1.26.4, PyYAML 6.0.2). \tc{make train SUBSET=50} runs the same code on 50 records as a smoke test.
Outputs: \tc{training/loss.csv} (one value per epoch), \tc{model.safetensors} and tokenizer, \tc{model.sha256} and \tc{run_info.json} (actual library versions) under \tc{training/output/<version>/}; \tc{scripts/upload.py} copies the directory to \tc{s3://models/v1}, and \tc{make package} (\tc{scripts/package_model.py}) builds a deterministic \tc{v1.tar.gz} with its \tc{.sha256} and \tc{release_manifest.json}; it refuses to run without trained weights, so no empty archive or invented checksum can be produced (tested \evA).
The second version (v2) differs by one recorded setting (another seed via \tc{--seed}, or an extra epoch) and is the target of the rolling update in Task 4.

\textbf{Evaluation protocol.} The instructor's \tc{score.py} is run on \tc{validation.jsonl} (100 commands, never trained on) for three raw-output files: the teacher (\tc{tools/predict_teacher.py}: same prompt file and options as Task 1), the untrained Pythia-70M, and the student.
Reported: JSON validity, intent/date/time/place accuracy and full-frame. Expected qualitative outcome \evP: the untrained model scores near 0\% validity; the student improves sharply but cannot exceed the teacher's slot accuracy, because it imitates the teacher's \emph{errors} too.

The assignment's four-record scoring example (V001--V004) yields validity 75, intent 50, date 50, time 75, place 75 and full-frame 25 \evC (derived by hand from the specification).

\textbf{Sequence-level vs.\ logit-based distillation.} \emph{Sequence-level} distillation (this project) trains the student on the teacher's \emph{generated outputs} as hard targets: the student sees one decoded string per input. \emph{Logit-based} distillation (e.g.\ the TRL distillation trainer) trains the student to
match the teacher's per-token probability distribution (KL divergence), which also transfers information about near-miss tokens. It is not possible here because the project fixes an Ollama-served Phi-3.5, which returns text rather than logits, and because teacher and student have different tokenizers, so
the distributions cannot be aligned token by token. \textbf{Limitation of my approach:} greedy single-sample labels freeze the teacher's mistakes into the dataset, and with only 1{,}500 examples and 70M parameters the student has no mechanism that guarantees valid JSON (no constrained decoding), so validity must be gated (Task 6).

\textbf{API.} Port 8000. \tc{GET /healthz} is 200 while the process lives; \tc{GET /readyz} is 503 until the background loader has downloaded the model from \tc{MODEL_URI} on \tc{S3_ENDPOINT} and loaded it (a loader failure is logged and leaves the pod not-ready);
\tc{POST /parse} validates every output against \tc{schema.json} and sets \tc{X-Model-Version} (from \tc{MODEL_VERSION}) and \tc{X-Served-By} (the pod name). \tc{MAX_NEW_TOKENS} bounds generation; credentials come only from a Kubernetes Secret.

\textbf{Container.} \tc{python:3.11-slim}, CPU-only \tc{torch==2.4.1} from the PyTorch CPU index (the default wheels pull GPU libraries), every other dependency pinned, no weights in the image, non-root user (uid 10001), and a \tc{.dockerignore} that keeps data, models and results out of the build context.
Size limit: 2\,GB. The fp32 weights alone are about $70.4\text{M}\times4\,\text{B}\approx0.28$\,GB \evC, which is why they live in object storage and are fetched at start-up.

\textbf{What was actually run.} The 32-test suite (API success and headers, bad intent, extra key, \tc{FAULT_INJECT}, health and ready, cleaning, sharding, manifests, CI order, cost, SLO) passes \evA (\tc{results/pytest_local.txt}).
\tc{tools/demo_server.py} runs the \emph{real} \tc{app.py} with a keyword-rule \textbf{stub} instead of Pythia-70M: \tc{/healthz} returned 200, \tc{/readyz} 200, a valid \tc{/parse} carried both headers, and \tc{FAULT_INJECT=1} gave HTTP 500 with the exact error body \evA (\tc{results/demo_api_stub.txt}).
A 20\,s Locust run (4 users) against the stub completed 209 requests with 0 failures at 11.0 req/s \evA. This only proves that the Locust file, header counting and CSV output work; it says nothing about the real service \textbf{(stub, not a performance result)}.

\textbf{HPA arithmetic} \evC: $\text{desired}=\lceil \text{current}\times \text{utilisation}/\text{target}\rceil$. Under load, 2 replicas at 140\% give $\lceil2\cdot140/70\rceil=4$, clipped to the maximum 2; at idle, 2 replicas at 20\% give $\lceil2\cdot20/70\rceil=1$.

\textbf{Test procedures} \evP, all run while Locust is generating load with a longer \tc{--run-time}: (i) \emph{load balancing} --- with exactly two Ready replicas count \tc{X-Served-By} in \tc{results/loadtest_headers.json}; each replica should serve at least 30\% of the successes; (ii) \emph{rolling update} ---
\tc{kubectl -n app set env deploy/command-parser MODEL_VERSION=v2 MODEL_URI=s3://models/v2}, target at most 0.5\% failed requests (supported by \tc{maxUnavailable=0} plus readiness gating), then \tc{kubectl rollout undo} and confirm that \tc{X-Model-Version} is v1 again;
(iii) \emph{recovery} --- delete one Pod under load; the replica count must return to 2 with at most 2\% failures; (iv) \emph{cold start} --- delete all Pods, show the download in the logs, and report the median Pod-creation-to-Ready time over three runs; (v) \emph{HPA} --- watch \tc{kubectl get hpa -w} scale 1 to 2 under load and back.
\textbf{Limitation (required statement):} the cluster runs on one laptop, so the two ``nodes'' share one machine, one disk and one power supply; this demonstrates Kubernetes self-healing, not fault tolerance across machines. My reflection reports a cold start of 18.0\,s \evS (unverified).

\textbf{NACL for the public subnet} (\tc{network/nacl.json}; lowest rule number first, first match wins, default deny):
\begin{center}\small\begin{tabular}{@{}llllll@{}}\toprule
Dir. & Rule & Protocol/ports & Peer CIDR & Action & Purpose\\\midrule
in & 100 & all & 198.51.100.0/24 & deny & abusive range; must precede 110/120\\
in & 110, 120 & tcp 80, 443 & 0.0.0.0/0 & allow & web traffic\\
in & 130 & tcp 22 & 10.20.5.128/27 & allow & SSH from management only\\
in & 140 & tcp 1024--65535 & 10.20.0.0/22 & allow & replies from the app subnet\\
out & 100 & tcp 8000 & 10.20.0.0/22 & allow & load balancer to app pods\\
out & 110 & tcp 1024--65535 & 0.0.0.0/0 & allow & replies to clients (ephemeral ports)\\\bottomrule\end{tabular}\end{center}
\textbf{Why replies need their own rules.} A NACL is \emph{stateless}: it does not remember connections, so a reply is a new packet judged on its own and needs an explicit allow on the ephemeral port range; a stateful security group would allow it automatically.
\textbf{Why order matters.} Because the first match wins, the deny for 198.51.100.0/24 must have a lower number than the allows for ports 80 and 443; if it were numbered above 110, traffic from that range would already have matched the allow. A side effect worth noting: outbound rule 110 also permits TCP 8000 to \emph{any} address, since 8000 lies in 1024--65535.
\textbf{Evidence.} My own evaluator \tc{tools/nacl_eval.py} decides all 11 hand-written packets as expected (11/11) \evA (\tc{results/nacl_eval_local.txt}). The instructor's \tc{nacl_sim.py} and its six sample packets are not in the repository and were not run \evP.

\section{Task 7 --- Performance, cost, SLO and review}
\textbf{Procedure} \evP. Standard run: \tc{locust -f tools/locustfile.py --headless --users 4 --spawn-rate 4 --run-time 2m --host http://localhost:8080 --csv results/loadtest}. Report p50 and p95 (\tc{loadtest_stats.csv}), throughput (req/s), error rate (failures divided by requests; a failure is anything but HTTP 200 within 30\,s),
per-Pod CPU and memory from \tc{kubectl top pods} sampled during the run, and the cold-start median from Task 4. Targets: error rate at most 1\%, p95 at most 5{,}000\,ms.

\textbf{Cost method.} $C_h = r\,(c\,P_{\text{cpu}} + m\,P_{\text{mem}})$ with $r$ replicas billed at their CPU and memory \emph{limits}, and $\text{cost per 1000 req}=C_h / (3600\cdot\text{rps})\times 1000$.
With the exercise prices (3.50 INR per vCPU-hour, 0.45 INR per GiB-hour; hypothetical exercise rates, consistent with my reflection's 7.90 INR/h) and 2 replicas of 1 vCPU and 1\,GiB: $C_h = 2(3.50+0.45)=7.90$ INR/h \evC.
